Modeling runs in order, with an inner loop: **baseline** (heuristic or simple model) → **model selection** (quality vs latency vs cost) → **training setup** (loss, splits, imbalance) → **scaling training** (distributed, hardware) → **tuning and debugging** (hyperparameters, overfitting, tracking).

## The multi-stage ranking funnel

For recommendation and search, one model can't score millions of items within the latency budget. Each stage trades speed for quality:

<Diagram src="modeling/multi-stage-ranking-funnel.svg" />

| Stage | Candidates | Model | Optimizes for |
|---|---|---|---|
| Retrieval | Millions → ~1,000 | Two-tower embeddings + approximate nearest-neighbor (ANN) search | Recall |
| Ranking | ~1,000 → ~100 | Heavy model with rich features | Precision |
| Re-ranking | ~100 → ~10 | Rules on top of scores | Diversity, freshness, business rules |

If you name this funnel in a recommendation or search interview, you've covered the core architecture.

## MLOps components modeling relies on

Model registry, model serving and similar pieces aren't stages; they're the **platform** stages 3–8 run on.

<Diagram src="modeling/mlops-platform-components.svg" />

The middle column is the key: the feature store and model registry are how the offline and online sides share things. The feature store prevents **training-serving skew**; the registry versions every model with its lineage and stage (`staging` → `production` → `archived`), so rollback means pointing back to the previous version. CI/CD for ML tests code, data and models before anything ships.

| Stage | Components used |
|---|---|
| Data | Warehouse, data versioning (DVC, lakeFS) |
| Features | Feature store (Feast, Tecton) |
| Modeling | Training jobs, experiment tracking (MLflow, W&B) |
| Evaluation | Experiment tracking, CI/CD |
| Deployment | Model registry, serving (Triton, KServe), rollout |
| Monitoring | Monitoring, orchestration (Airflow, Kubeflow) to retrain |

## Running example: Bazaar

Bazaar is an e-commerce marketplace whose home feed ranks products for each user. The business goal is to grow GMV (gross merchandise value).
