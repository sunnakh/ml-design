The data stage is a pipeline of 6 steps, with 4 risks that can break any of them.

<Diagram src="data/data-stage-subtopics.svg" />

1. **Sources**: user interaction logs, application databases, third-party data, and labels from people. Ask where each comes from, how fresh it is, and who owns it.
2. **Ingestion**: batch jobs (daily ETL into a warehouse) or streaming (Kafka → Flink). Use streaming only when features must be fresh within seconds.
3. **Labeling**: often the hardest step. Human labels are accurate but slow and expensive. Implicit labels (clicks, purchases) are cheap but noisy and biased toward what was shown. Weak supervision uses rules or an LLM. Watch for delayed labels.
4. **Cleaning**: deduplicate, handle missing values and outliers, validate the schema (Great Expectations, TFDV).
5. **Sampling and splits**: handle class imbalance (downsample, upweight, focal loss). Split by time, not randomly, whenever the data has a time order.
6. **Storage**: a lake or warehouse with dataset versioning (DVC, Delta Lake) and lineage, so any training run can be reproduced.

## Running example: PayFlow

PayFlow processes card payments for online merchants. For every payment it has **under 100 ms** to score the transaction for fraud and approve, block, or send it to manual review.

- about 5,000 transactions per second
- a fraud rate of about 0.1%
- confirmed fraud arrives as a **chargeback** 30 to 90 days later
